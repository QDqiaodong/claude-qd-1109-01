# 养蜂场 · 蜂箱台账与采蜜批次

养蜂场业务管理：蜂箱台账、蜂箱巡检（月历视图，按蜂箱+日期唯一，含健康判定、异常处置、负责人/截止日期/现场说明、唯一复检与逾期提醒）、采蜜批次、蜂蜜批次质检放行（初检、隔离整改、唯一复检、拒绝入库与入库联动）、客户管理。

## 技术栈
- 后端：Spring Boot 3.3 + Spring Data JPA + MySQL
- 前端：Vue 3 + Element Plus + Vite

## 启停
```bash
sh start.sh     # 启动（docker compose 拉起 mysql + backend + frontend）
sh stop.sh      # 停止
```

## 蜂箱巡检 · 异常处置与复检提醒
- 月历按「蜂箱 + 日期」唯一，跨月查看只切换视图，不会重复生成处置任务；风险蜂箱、逾期、待复检在月历格与列表中分别高亮。
- 蜂群健康为「一般 / 病态」的异常巡检必须先进入「待处置」并自动生成唯一处置项；处置措施、负责人、截止日期未填齐时不能标记完成（现场说明可补录）。
- 同一蜂箱存在未完成处置时，新巡检仍显示风险，后端与表单双重禁止把健康状态直接登记/改回「健康」。
- 处置完成进入「待复检」，每条处置只能发起一次复检：复检合格才解除提醒（已解除）；复检不合格保留原异常与历史处置，自动重新生成一轮待处置项，截止日期自上轮截止/复检日顺延 7 天，页面标记为「连续异常·第 N 轮」。
- 看板同时支持按健康状态、处置状态（待处置 / 逾期 / 待复检 / 复检不合格 / 已解除）、截止日期区间与蜂箱筛选，逾期、待复检、连续异常、已解除用不同标签区分。
- 删除蜂箱为软删除：台账不再显示，但关联巡检、处置与复检历史全部保留可追溯，箱号可重新建档；把巡检移到其他蜂箱时处置/复检链路整体跟随。

## 蜂蜜批次质检放行
- 质检记录包含抽样编号、含水率、感官结论、检测人、检测时间、说明及初检/复检轮次。
- 抽样编号全库唯一；同一批次仅允许一条生效中的质检记录，复检后旧记录保留为历史。
- 含水率 ≤ 20% 且感官合格时放行；任一不合格即进入「隔离待整改」。
- 隔离批次必须先登记整改说明，整改后最多复检一次；复检仍不合格进入「隔离拒收」并禁止入库。
- 只有「质检放行」或「复检合格」批次可通过原入库动作进入「已入库」。
